# 一生一芯 2306 C 阶段加速讲义

> 对应原讲义 `basic/1.1.md`--`basic/1.6.md`，即 C1--C6。本文把任务按“理论前置 -> 最小实现 -> 分层验证 -> 阶段出口”重排，方便连续推进。PA 讲义、RISC-V 手册、Verilator 手册和仓库 README 仍是接口细节与最终验收的依据。

## 1. C 阶段目标

C 阶段要完成从“能模拟指令”到“能在自己设计的单周期处理器上运行操作系统”的迁移：

```text
RV32IM NEMU (C1)
  -> RTL 最小 NPC (C2)
  -> AM/运行时与调试基础设施 (C3)
  -> RV32E 单周期 NPC + DiffTest (C4)
  -> MMIO、串口、时钟和红白机字符版 (C5)
  -> 异常/CSR/ecall/mret + RT-Thread (C6)
```

完成 C6 后可以申请 C 阶段结业考核；只有通过 C 阶段考核，才具备参加 B 阶段流片考核的资格。

### 总体验收

- [ ] NEMU 完成 PA2 阶段 1--3 的对应内容，并能运行 RV32IM 程序。
- [ ] NPC 能从命令行加载 AM 程序，自动执行到 `ebreak`，输出 `HIT GOOD`/`HIT BAD`。
- [ ] NPC 支持 RV32E 必需指令、访存、`itrace`/`mtrace`/`ftrace`、DiffTest，所有 `cpu-tests` 通过。
- [ ] NPC 能运行 `hello`、实时时钟测试和字符版红白机游戏。
- [ ] NEMU 与 NPC 均能启动 RT-Thread；学习记录中有测试命令、失败现象和定位过程。

## 2. 通用推进方法

每个 C 阶段任务都按以下闭环执行：

1. **画边界**：写清当前模块的输入、输出、状态、时钟关系和上游/下游。
2. **做最小功能**：一次只加入一条指令、一个设备或一个调试接口。
3. **保留证据**：保存编译命令、程序输出、trace、DiffTest 报告或波形。
4. **分层定位**：先用程序/指令/访存级工具缩小范围，再用 RTL 波形定位信号。
5. **回归**：每次修改后重跑已有测试；不要只验证刚刚新增的用例。

**[原则] RTFM + STFW + RTFSC。** 指令语义看 ISA 手册，工具行为看官方文档，框架行为读源码。提问前给出环境、复现命令、预期、实际结果、已尝试方案和最小复现；不要用他人代码、往届攻略或“改到能跑”为替代理解。

**[原则] 工具也是项目的一部分。** 波形是最低层证据，不能替代 `sdb`、trace、DiffTest 等高层工具。高层工具定位大致范围，波形只分析小窗口和精确时序。

## 3. C1：支持 RV32IM 的 NEMU

对应原讲义：`basic/1.1.md`；必做内容是 PA2 阶段 1，直到 PA 讲义出现“PA2 阶段 1 到此结束”。

### 目标

把 PA1 的最小 NEMU 扩展成可执行 RV32IM 程序的模拟器，为 RTL 实现提供可观察、易调试的参考模型（REF）。核心是理解指令取指、译码、执行、访存和 PC 更新，而不是机械填满 `TODO`。

### 必备理论

- RISC-V `rv32i` 基础指令格式、立即数符号扩展、`x0` 恒为 0、PC 相对寻址。
- `M` 扩展的乘除法语义及有符号/无符号组合。
- ELF/程序装载、批处理运行和 NEMU monitor 的调用关系。
- 指令级状态机：执行一条指令前后的 PC、GPR、内存和异常状态。

### [必做] 推进顺序

1. 按 PA2 阶段 1 完成指令执行框架和 RV32IM 指令实现。
2. 先通过单条指令和 `cpu-tests`，再运行更大的测试程序；每新增一类指令立即回归。
3. 检查 `x0` 写入被丢弃、立即数扩展正确、分支/跳转 PC 正确、访存宽度和符号扩展正确。
4. 完成 PA 提示框后再进入 C2；不要把未通过的 NEMU 当作 NPC 的参考模型。

### C1 出口

能解释一个 RV32IM 程序从装载到 `exec_once()` 返回的完整路径，并能用 trace 或调试器定位一次错误指令。

## 4. C2：用 RTL 实现最简单的处理器

对应原讲义：`basic/1.2.md`。

### 目标与架构

用 RTL 实现只支持 `addi` 和 `ebreak` 的最小单周期 NPC。建议先画图，再拆成：

- **PC/更新逻辑**：复位值为 `0x80000000`，顺序执行时按指令长度递增。
- **IFU**：按 PC 获取指令；本阶段指令存储器由 C++ 仿真环境提供。
- **IDU**：解析 opcode、寄存器编号、立即数和控制信号。
- **EXU/写回**：完成加法并写 GPR；`x0` 读出恒为 0、写入无效。
- **DPI-C 边界**：RTL 与 C++ 之间传递取指、停机等事件。

### [必读] RTL 风格约束

- 初学者不要把 Verilog 当作 C 语言写；优先用数据流和结构化建模表达“实例化 + 连线”。
- 不清楚事件队列、阻塞/非阻塞赋值和敏感列表时，不要自行扩展复杂 `always` 行为建模；先读 Verilog 标准或使用讲义模板。
- 行为模型中不要使用 `negedge` 或无意引入锁存器。
- Verilog 模块名需添加学号前缀（如 `ysyx_XXXXXXXX_IFU`），宏标识符同样前缀；使用 Chisel 时按讲义规定处理生成名。

### [必做] 实现路径

1. 在 `npc` 中画出仅支持 `addi` 的数据通路，明确 PC、取指、寄存器读写、立即数和 ALU 的连接。
2. 在存储器中放置若干条 `addi` 编码，执行固定周期，观察寄存器或波形确认写回。
3. 添加 `ebreak`，阅读 Verilator 手册中的 DPI-C 示例。
4. 让 RTL 执行 `ebreak` 时通知 C++ 仿真环境退出；此后仿真循环不再依赖预先猜测的指令条数。

### C2 出口

- [ ] `addi` 的正数、负数和 `x0` 源/目的寄存器测试通过。
- [ ] PC 复位、顺序递增和寄存器写回时序可从波形解释。
- [ ] `ebreak` 能自动结束仿真，C++ 端能区分正常结束和异常退出。

## 5. C3：运行时环境和基础设施

对应原讲义：`basic/1.3.md`；必做内容是 PA2 阶段 2，直到 PA 讲义出现“PA2 阶段 2 到此结束”。

### 目标

理解程序与硬件之间的运行时环境（AM/运行时库、启动代码、链接和加载），并把 NEMU 中验证过的调试思想迁移到 NPC。没有运行时环境，RTL 只能执行手写机器码，无法持续运行真实程序。

### [必做] 推进顺序

1. 按 PA2 阶段 2 完成 AM 运行时、程序构建/链接和客户程序装载。
2. 明确 ELF/镜像由谁生成、由谁加载到内存、PC 从哪里开始执行、`halt()` 如何反馈结果。
3. 将 NPC 的 C++ 仿真环境改造成可接收程序镜像，而不是每换一个程序就重新编译 RTL。
4. 为后续 `sdb`、trace、DiffTest 保留稳定的执行入口、寄存器快照和内存访问接口。

### 关键接口

```text
AM 程序 -> 启动代码/链接脚本 -> ELF/镜像
        -> NPC C++ 装载 -> pmem_read/pmem_write
        -> RTL 取指/执行 -> halt/trace/DiffTest
```

### C3 出口

能说明“源程序如何变成 NPC 可以取指的字节”，并能从命令行替换待运行程序而不修改 RTL 源码。

## 6. C4：支持 RV32E 的单周期 NPC

对应原讲义：`basic/1.4.md`。这是 C 阶段的核心工程阶段：先让最小程序跑起来，再补齐 RV32E、调试设施和访存。

### 6.1 运行时与程序加载

AM 已提供 `riscv32e-npc` 框架。典型编译命令：

```bash
cd am-kernels/tests/cpu-tests
make ARCH=riscv32e-npc ALL=xxx
```

实现或补齐 `riscv32e-npc` 的 `run` 目标，使下面的形式可以“一键编译并运行”：

```bash
make ARCH=riscv32e-npc ALL=xxx run
```

程序装载路径必须清楚：命令行参数 -> C++ 读取 ELF/镜像 -> 写入仿真内存 -> PC 从 `0x80000000` 取指。若对此不清楚，回看 NEMU 的镜像装载实现。

### 6.2 [必做] 先跑 dummy

为使 `dummy` 运行，逐步实现：

- `auipc`、`lui`：与已有加法器共享可复用数据通路；
- `jal`、`jalr`：修改下一条 PC，并写回返回地址；
- `sw`：dummy 阶段可暂作空操作，但在完整访存阶段必须按写掩码正确实现；
- `halt()`：在 AM 的 `riscv32e-npc` 实现 `ebreak`，让程序主动结束；
- `HIT GOOD`/`HIT BAD`：从 `ebreak` 或 trap 结果反馈程序是否成功。

每完成一组指令都应使用波形或 trace 检查 PC、寄存器和控制流，不要只看最终退出码。

### 6.3 [必做] NPC 调试基础设施

#### SDB

实现单步执行、寄存器打印、内存扫描。寄存器可通过 DPI-C 访问，或读取 Verilator 生成的 C++ 层级变量；后者依赖生成的层级名字，升级 Verilator 或改 RTL 后要重新核对头文件。

#### Trace

- `itrace`：获取当前指令并打印反汇编；需要通过 DPI-C 取得指令，并按 NEMU 的方式链接 LLVM 反汇编库。
- `ftrace`：在指令流基础上跟踪函数调用/返回。
- `mtrace`：在访存接口稳定后记录读写地址、数据和掩码。

#### DiffTest

推荐 DUT=NPC、REF=NEMU。先把 NEMU 编译成共享库，在 `nemu/src/cpu/difftest/ref.c` 实现 `difftest_memcpy()`、`difftest_regcpy()`、`difftest_exec()`；`difftest_raise_intr()` 此阶段暂不使用。NPC 通过动态链接调用这些 API。

用故意把 `addi` 写错的方式验证 DiffTest 确实能报告首个状态差异；验证后恢复实现，并把 NEMU 的构建目标切回 ELF。

**[提示]** 2306 优先使用自己实现的 NEMU 作为 REF，因为后续可以按项目需要修改；Spike 仅是可选替代方案。

### 6.4 [必做] RV32E 指令与访存

在 NEMU 中已经理解过的 RV32E 指令，迁移到 RTL 时按类别实现并逐类回归：

- ALU：加减、逻辑、移位、比较；补码减法可复用加法器，分支比较也可复用减法结果。
- 控制流：条件分支、`jal`、`jalr`；检查目标地址和链接地址。
- 访存：`lb/lh/lw/lbu/lhu`、`sb/sh/sw` 等，处理对齐地址、字节选择、符号扩展和写掩码。

NPC 的内存接口建议统一为 32 位对齐访问：

```c
extern "C" int pmem_read(int raddr);              // 读取 raddr & ~0x3u 的 4 字节
extern "C" void pmem_write(int waddr, int wdata,
                            unsigned char wmask);  // 每一位对应一个字节
```

RTL 根据低地址位从对齐读数据中选择字节/半字，并在写入时生成正确 `wmask`；C++ 端只更新掩码覆盖的字节。取指也通过同一套读接口完成，避免后续总线接入时重复改造。

### 6.5 [必做] 回归与综合观察

- 运行全部 `cpu-tests`；失败时先看 DiffTest、itrace 和 mtrace，再看对应周期波形。
- 用 `yosys-sta` 对 ALU 做综合，比较减法/比较/分支是否复用加法器、移位运算综合成何种电路，并尝试缩小位宽到 4/8/16 位观察网表。
- 记录 RV32E 不含 `M` 扩展的原因：编译器会把乘除法降级为 `__mulsi3()` 等 `libgcc` 软件例程，因此不需要硬件乘除法即可运行相应 C 程序。

### C4 出口

NPC 能通过 `make ARCH=riscv32e-npc ALL=xxx run` 运行 AM 程序并自动结束；所有 CPU 测试通过；一次注入错误能被 DiffTest 捕获；能用 trace 和波形解释一条访存或分支指令。

## 7. C5：设备和输入输出

对应原讲义：`basic/1.5.md`。NEMU 侧完成 PA2 阶段 3，直到 PA 讲义出现“PA2 到此结束”。

### 目标与理论

RISC-V 通过 MMIO 把设备映射到地址空间。此阶段先在 NPC 仿真环境的 `pmem_read()`/`pmem_write()` 中按地址重定向设备，不急于实现 RTL 总线；AM 的 IOE 抽象保证同一份应用代码可运行在 NEMU 与 NPC 上。

### [必做] 设备推进

1. 在 NEMU 完成 PA2 阶段 3 的输入输出内容。
2. 在 NPC 的 `pmem_write()` 实现串口输出，运行 `hello`。
3. 在 `pmem_read()` 实现时钟，运行 `am-tests` 的 `real-time clock test`；时间获取方式自行 STFW 系统时间 API。
4. 运行字符版红白机模拟器。

设备访问必须尊重对齐读和字节写掩码；不要把设备地址当普通 RAM 静默吞掉，否则后续软件错误会被掩盖。

### [扩展阅读]

仿照 NEMU 实现 VGA，运行 video 测试和图形版红白机游戏。VGA 不属于本阶段主线出口，不应替代串口、时钟和字符版游戏验收。

## 8. C6：异常处理和 RT-Thread

对应原讲义：`basic/1.6.md`。

### 目标

完成 CTE（上下文/异常运行时），使 NEMU 和 NPC 能响应 `ecall` 并启动 RT-Thread。此阶段把“程序主动退出”扩展为“硬件把控制权交给异常处理程序”。

### [必做] NEMU 先行

1. 按 PA3 阶段 1 完成自陷操作，直到“PA3 阶段 1 到此结束”。
2. 按 PA4 阶段 1 启动 RT-Thread；后续 Nanos-lite 内容暂不要求。
3. 记录异常入口、`mepc`/`mcause`/`mtvec` 的变化，确认返回路径。

### [必做] NPC 最小异常机制

只实例化运行 RT-Thread 实际用到的少量 CSR，不要为 4096 个地址全部生成寄存器阵列。2306 主线的最小实现包括：

- 必要 CSR 的读写和正确初始化（通过 DiffTest 检查）；
- 少量 CSR 指令，注意它们对同一个 CSR 的原子读-改-写语义；
- `ecall`：设置 `mcause` 和 `mepc`，跳转到 `mtvec`；
- `mret`：从 `mepc` 返回；
- 异常响应相关的下一地址选择和状态更新。

现阶段可暂不实现未被程序使用的 CSR 字段副作用，以及 WPRI/WLRL/WARL 等复杂写入属性；这不是对完整 RISC-V 规范的否定，而是教学阶段的明确范围。后续运行更多软件时再逐步补齐。

### C6 出口

- [ ] NEMU 启动 RT-Thread。
- [ ] NPC 实现最小异常处理并启动 RT-Thread。
- [ ] 能解释一次 `ecall -> mtvec -> mcause/mepc -> mret` 的状态转移。
- [ ] 观察并记录 NPC 最后一个 `msh />` 提示符缺失问题；可暂时保留为后续 SoC 阶段的待办，不把它误判为核心异常机制未完成。

## 9. 调试决策表

| 现象 | 首选工具/检查 | 再进入波形前确认 |
| --- | --- | --- |
| 程序立即退出或 `HIT BAD` | `itrace`、寄存器打印、`ebreak` 路径 | PC、返回码、`x0` 是否保持 0 |
| 指令结果与 NEMU 不同 | DiffTest、反汇编、立即数/符号扩展 | DUT/REF 初始内存与寄存器一致 |
| 访存结果错误 | `mtrace`、地址对齐、读写掩码 | 读数据选择、写字节使能、符号扩展 |
| 分支/跳转跑飞 | `ftrace`、PC 序列、目标地址计算 | `jalr` 低位清零、链接地址为 `pc+4` |
| `hello` 无输出 | MMIO 地址、`pmem_write`、写掩码 | 串口写入是否被当作 RAM 丢弃 |
| 时钟测试失败 | `pmem_read`、系统时间 API、单位换算 | 返回值单调、宽度和地址匹配 |
| RT-Thread 卡住 | `ecall`/`mret` trace、CSR 快照 | `mtvec`、`mepc`、`mcause` 和异常入口 |

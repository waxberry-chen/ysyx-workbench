## 1. 当前实现范围

目标软件仍为 `-march=rv32e_zicsr -mabi=ilp32e`；RTL 实现 16 项 GPR、RV32E 基础整数编码及下述最小机器态 CSR 契约，不含 M/C。与首次综合相比，这是功能范围收敛，不能将后续面积下降称作同 ISA 的乘除法优化。

| 类别 | 支持与检查 |
| --- | --- |
| 整数运算 | ADD/SUB、SLL/SRL/SRA、SLT/SLTU、XOR/OR/AND 及对应立即数形式，LUI/AUIPC；检查 R 型 funct7 和移位立即数高位 |
| 控制流 | JAL、funct3=0 的 JALR；BEQ/BNE/BLT/BGE/BLTU/BGEU |
| 访存 | LB/LH/LW/LBU/LHU、SB/SH/SW；保留已有数据地址未对齐 cause 4/6 和访问错误 cause 5/7 |
| 顺序约束 | FENCE 作为 no-op：本核逐条提交、此前 LSU 操作已完成；忽略其保留 fm/rd/rs1 字段。不支持 FENCE.I |
| SYSTEM | 精确识别 ECALL、MRET；六种 Zicsr 仅能访问下表四个 CSR；EBREAK 保留 harness 退出约定 |
| 明确拒绝 | 八条 M 指令、C/其他未实现扩展、未知 opcode、保留 funct3/funct7、错误 SYSTEM 编码、未实现 CSR 地址，均 cause 2 |

RV32E 的 x16–x31 编码属于保留范围，本项目选择触发 illegal instruction；不把此策略说成所有实现唯一的规范选择。IDU 仅检查实际使用的 rd/rs1/rs2：例如 I 型 inst[24:20]、U/J 型立即数、CSR zimm 都不是 GPR 编码。`csrrwi ..., 31` 合法，使用 x31 作为 CSR 寄存器源则非法。

regfile 物理数组由 32 缩为 16 项，x0 两个读口硬连零、写 x0 无效；x1–x15 显式异步复位到零。高索引在 regfile 层也不截断别名访问，以防未使用的译码字段误读低寄存器。ALU 已删除八个 M 分支及乘积临时数据，仿真/综合没有不同的 ISA 开关。AM 已使用 RV32E 编译及软件乘除辅助例程，无需修改编译目标；本次 div、matrix-mul、mul-longlong 等回归通过。

## 2. CSR 与 trap 契约

当前只有 M 模式，不提供 S/U 模式。四个地址均为机器态可读写寄存器；未实现地址（含 `misa`、`mscratch`、`cycle`）即使只读、rd=x0 或零操作数也报非法，不返回 mstatus 的别名。

| CSR | 地址 | reset / 普通写入语义 |
| --- | --- | --- |
| mstatus | 0x300 | reset=0x1800；MPP 固定 3，仅 MIE(bit 3)/MPIE(bit 7) 可写，其他位为零 |
| mtvec | 0x305 | reset=0；只支持 Direct，写入清低两位 |
| mepc | 0x341 | reset=0；IALIGN=32，普通写入及 trap 保存均清低两位 |
| mcause | 0x342 | reset=0；普通写入保存 32 位；trap 写入实际 cause。无中断生成，不代表全部 cause 均实现 |

CSRRW/CSRRS/CSRRC 与 CSRRWI/CSRRSI/CSRRCI 分别执行替换、置位、清位；rd 接收写入前的值，立即数源零扩展。RS/RC 的写抑制检查的是编码中的 rs1=x0 或 zimm=0，不是“某个非零寄存器恰好保存零”。RW 即使源为零仍写入；rd=x0 时不需要读回。当前 CSR 无读副作用，组合读 mux 无单独 read-enable；不将物理读 mux 的活动等同于架构上的 CSR 读副作用。未来新增带读副作用 CSR 时必须扩充接口。

精确异常在 EXU 的 commit 边界完成：非法指令保存自身 PC 到 mepc、写 mcause=2，MIE→MPIE、MIE=0、MPP=3，并 redirect 到 mtvec；不产生原指令的 GPR/普通 CSR 写入或 LSU 请求。非法访存编码直接完成 trap，不等待不存在的响应。取指 access fault cause 1 优先于返回数据的非法编码；无效/被取消上下文不提交异常。MRET 恢复 MIE←MPIE、MPIE=1、MPP=3，并跳到 mepc；ECALL 仍为 cause 11。

**合规边界**：这不是完整 privileged architecture 或完整 ISA compliance 认证。没有中断递送、misa/mtval/mie/mip/mstatush、PMP、S/U 等能力；EBREAK 仍是仿真终止标记，硬件不生成 breakpoint cause 3。现有控制流目标未对齐的 cause 0 路径也未在本步骤补齐，不应把无 C 和 mepc 对齐掩码表述成已经覆盖所有取指对齐异常。上述边界需在后续集成要求出现时单独收敛。

## 3. 跨层适配与发现的问题

- harness 的实际 RTL 指针只复制、遍历 16 项，DPI 注册时检查数组长度。保留 `CPU_state.gpr[32]` 作为既有 DiffTest ABI，高 16 槽每次清零；它们不是新增硬件寄存器，参考端仍可检查这部分保持为零。
- NEMU 保留自身的 M 指令能力。本次补齐六种合法 CSR 操作、FENCE 及对应四 CSR 写入/复位语义；立即数 CSR 不走 GPR 源读取，兼顾 NEMU 的 RVE 配置。未将 NEMU 全局裁剪为 NPC 的非法编码检测器。
- 端到端测试发现：旧 harness 在 reset 前把全零状态复制给参考端。现在改为 reset 后同步真实架构状态，保证 MPP=3 一致。CSR 的 DPI 指针直接连接持久寄存器存储，避免对组合表达式临时值保存指针。
- DiffTest 会按 DUT 提供的 cause 注入异常，因而不能证明 DUT “应该报非法”。本次专门增加独立掩码表译码检查，以及带自检查 handler 的 `.word` 程序；参考比较只作附加状态检查。

### legacy trace 的有依据更新

mstatus reset 从 0 改为 0x1800，因此含 CSR 的架构状态 hash 必须变化。add 程序没有 CSR 操作（仅 EBREAK），本次对 1095 行逐一逆向展开 FNV-1a 的末尾四个 CSR 字段，将 mstatus=0x1800 还原为旧值 0 后重新计算，精确得到旧总 hash；证明该固定程序的 PC/inst/npc/GPR/其他 CSR 均未变化。该验证不是一般程序等价证明。

- 旧值：`bbf8496edf2329d695eb4437641ced89bba9cf0b6006f1a0b5955c32941e9284`
- 新值：`d18898e78483a270397c27594904e2fd520d84b7dc7c7dbac9401790f6d34392`

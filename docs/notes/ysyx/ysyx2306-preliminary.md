# 一生一芯 2306 预学习加速讲义

> 对应原讲义 `preliminary/0.1.md`--`0.7.md`。本文件把网页讲义重排成可执行路径，适合每天推进和复盘；原讲义、PA 讲义和工具手册仍是任务细节的最终依据。

## 0. 目标与出口

预学习不是筛选赛，而是进入正式阶段前的能力检查。完成后应能独立搭建环境、读懂并修改 C/Verilog、用 Verilator/NVBoard 调试小电路，并完成 PA1 的简易调试器基础。

**出口条件（全部满足才申请答辩）：**

- [ ] 每天填写学习记录；记录问题、尝试、证据和结论。记录模板需复制到自己的账号并开放“可查看”。
- [ ] 通识问卷达到 100 分；阅读课程报名/FAQ 和简历规范。
- [ ] 完成 Linux、C 语言、数字电路和 Verilator 的必做任务。
- [ ] PA1 完成到原讲义的“PA1 到此结束”提示，ISA 使用 `riscv32`。
- [ ] 两篇提问文章读后感不少于 800 字，并提交入学答辩申请。

**[必读] 预估时间只是基线。** 原课程对中等基础学习者给出约 89 小时的预估；零基础应按 2--3 倍安排，不要用压缩时间换取跳过训练。

## 1. 推荐推进节奏

每个学习单元固定执行：

1. **读目标**：先写下本单元要新增的知识、文件和可观察结果。
2. **最小实现**：只实现使一个最小测试通过的功能。
3. **观察证据**：保存命令、编译输出、断言、波形或调试器输出。
4. **回归与记录**：新增功能后重跑旧测试，并在学习记录中写“现象--假设--验证--结论”。

遇到问题时按 `STFW -> RTFM -> RTFSC -> 最小复现 -> 提问` 推进。提问必须包含环境、命令、预期、实际输出、已尝试方法和最小复现；不要直接索要答案或代码。

**[原则] 独立解决问题是训练目标。** 当讲义要求实现 X，必须独立完成；不要使用虚拟机镜像、一键脚本、攻略、往届代码或交换测试用例来绕过训练。看懂别人的代码不等于自己完成，短期省时会降低未来面对无攻略问题的能力。

## 2. 阶段一：提问与工作习惯（对应 `0.1`，约 2 h）

### 目标

建立可检索、可复现、可交流的问题解决流程；知道 `STFW`（Search The Friendly Web）、`RTFM`（Read The Fine Manual）、`RTFSC`（Read The Fine Source Code）分别何时使用。

### [必做]

- 阅读《提问的智慧》（一生一芯版），理解先搜索、读手册、读源码、给出最小复现的要求。
- 完成通识问卷（可重做，申请答辩前必须 100 分）。
- 阅读项目简历规范，后续只如实描述完成的阶段和产出。
- 在学习记录中写一次自己的提问模板，并尝试用它记录一个真实问题。

### [必读]

不要把“别人告诉我答案”当作学习。助教可以指出缺少的概念、手册或源码位置，但不应替代你的推理和实现；帮助别人时也不要直接交付答案。

## 3. 阶段二：Linux 与仓库（对应 `0.2`，约 10 h）

### 目标

具备命令行、编辑器、Shell、Git 和构建工具的基本工作能力，并把 PA0 与 ysyx 工作区连起来。

### [必做] 环境与仓库

1. 按 [PA0](https://ysyx.oscc.cc/docs/ics-pa/PA0.html) 安装 Linux 开发环境；发行版不限，但使用非课程常见发行版时要自行解决兼容问题。
2. 为 GitHub 配置 SSH key，然后在工作区外执行：

   ```bash
   git clone -b master git@github.com:OSCPU/ysyx-workbench.git
   cd ysyx-workbench
   ```

3. 阅读 PA0 时，把 PA 的项目目录 `ics2022` 映射为 `ysyx-workbench`；不要修改 PA 原讲义来硬编码 ysyx 内容。
4. 暂不必填写 `Makefile` 的学号；完成预学习后再填写真实信息。
5. 完成 MIT Missing Semester 的以下章节及课后题：课程概览与 Shell、Shell 工具和脚本、Vim、数据整理、命令行环境、Git。

### 最小自检

```bash
git status
git log --oneline -5
make --version
vim --version
```

**[必读] 安装过程本身就是训练。** 遇到依赖、权限或路径问题，先搜索错误文本、阅读手册和日志。不要直接换用他人镜像或一键配置脚本；这些“捷径”会掩盖你以后必须独立处理的系统问题。

## 4. 阶段三：C 语言（对应 `0.3`，约 20 h）

### 必备理论

掌握递归、指针（含指针运算和指针参数）、数组与字符串、结构体、链表、函数指针、内存生命周期、编译/链接基本过程，以及能独立写出并调试正确程序。Verilator 生成 C++ 代码，另需会读 class 的基本用法，不要求复杂 C++。

### [必做]

- 以《Learn C the Hard Way》为主线完成练习 0--18、32、33、42、44，并完成编程算法和附加题。
- 遇到卡点先 STFW；答辩允许使用前述学习资料和咨询助教，但实现必须自己完成。
- 用编译器警告和调试器检查程序，不以“能编译”作为正确性标准。

### 建议自检

能独立写出：动态数组、链表增删查、递归遍历、字符串处理、命令行参数解析、带断言的单元测试。至少说明每个指针的所有权、有效期和边界。

## 5. 阶段四：Verilator 仿真环境（对应 `0.4`，约 5 h）

### 目标与核心概念

理解 RTL（Verilog）模块、C/C++ testbench、Verilator 生成模型之间的关系：testbench 驱动输入，调用 `eval()` 计算组合逻辑或推进时序逻辑，再读取输出；时序电路需要显式产生时钟和复位。

### [必做] 建立 NPC 环境

```bash
cd ysyx-workbench
bash init.sh npc
```

确认目录至少包含 `npc/csrc/main.cpp`、`npc/vsrc/example.v`、`npc/Makefile`。若选择 Chisel，可执行 `bash init.sh npc-chisel`，但仍建议先用 Verilog 完整走一遍 Verilator 流程。

### [必做] 从组合到时序

1. 阅读 Verilator 官网和手册，按手册安装 **5.008** 版本；不要用发行版中可能过旧的 `apt` 版本。源码目录放在 `ysyx-workbench` 之外。
2. 用 `verilator --version` 验证版本；先运行手册 C++ 示例。
3. 编写双控开关 `f = a ^ b`，修改 testbench 的顶层模块名，随机驱动输入，用 `eval()` 后断言输出正确。
4. 阅读生成的 C++ 与原 Verilog，解释端口映射、`eval()`、断言和仿真循环。
5. 按手册生成波形，用 GTKWave 查看；优先使用 FST 格式。
6. 为 `npc/Makefile` 添加 `make sim` 一键仿真规则。

**[必读] 保留 Git 追踪命令。** 既有 `sim` 规则中的 `$(call git_commit, "sim RTL")` 用于记录仿真进展，不得删除或改写；运行后检查提交记录是否更新。

**[必读] 波形有磁盘风险。** 波形文件可能很大，长时间无界生成会耗尽磁盘并导致系统异常。限制仿真周期，优先 FST（约为 VCD 的 1/50，主要由 GTKWave 支持）。

### [必做] NVBoard 与流水灯

```bash
cd ysyx-workbench
bash init.sh nvboard
```

阅读 NVBoard 示例，理解 Verilog 顶层端口、约束文件、C++ testbench 和 Makefile 的连接关系；将双控开关接入 NVBoard 并分配引脚。再实现带复位和时钟分频的 16 位流水灯，执行“低电平/高电平各一次 `eval()`”的单周期循环，先复位若干周期，再观察 LED 依次移动。最后阅读生成代码，解释时序电路为何必须显式推进时钟。

## 6. 阶段五：数字电路（对应 `0.5`，约 20 h）

### 必备理论

二进制编码；组合逻辑（选择器、译码器、优先编码器、加法器、比较器、ALU）；时序逻辑（时钟、D 触发器、计数器、SRAM/DRAM、有限状态机）；建立/保持时间与基本时序分析。

### [必做] NVBoard/数字电路实验

使用南京大学《数字电路与计算机组成实验》或等价资料，完成：

1. 实验一：选择器；
2. 实验二：译码器和编码器；
3. 实验三：加法器与 ALU；
4. 实验六：移位寄存器及桶形移位器；
5. 实验七：状态机及键盘输入。

语言可选 Verilog 或 Chisel；选择 Chisel 时把生成的 Verilog 接入 Verilator/NVBoard。使用 HDLBits 等题库补充练习属于 `[扩展阅读]`，不替代上述必做实验。

### [必做] 综合后时序评估

```bash
git clone git@github.com:OSCPU/yosys-sta.git
```

按仓库 README 用 Yosys 综合 RTL、用 nangate45 映射并交给 iSTA，阅读最小时序余量路径，至少对一个数字电路实验做评估。遇到问题提交 RTL、SDC、Yosys 网表和 `echo exit | ./bin/iEDA -v` 的版本号。

**[提示] 评估边界。** Yosys 和 nangate45 与商业工具/工艺存在面积、频率和可制造性差异，因此把报告用于比较优化方向，不把绝对频率当作流片承诺。预学习阶段通常不需要 FPGA：软件仿真调试能力更强，FPGA 综合实现开销只有在仿真运行达到很长时间时才可能抵消。

## 7. 阶段六：PA1（对应 `0.6`，约 30 h）

### 为什么先做模拟器

PA 覆盖硬件模拟器、ISA、运行时环境、OS、库函数和应用程序；先在 NEMU 中实现更容易验证的系统，再把行为迁移到 RTL。模拟器也是处理器验证和差分测试的重要组件，不能当作与项目无关的黑盒。

### [必做]

1. 阅读 PA FAQ；需要理论补充时参考“计算机系统基础”课程资源。
2. 在 PA 讲义中选择默认 `riscv32`，完成：
   - 基础设施：简易调试器；
   - 表达式求值；
   - 监视点；
   - PA1 其余必答题，直到出现“PA1 到此结束”。
3. 每完成一个命令或表达式特性，使用正常输入、边界输入和错误输入做回归，并记录调用路径和状态变化。

## 8. 阶段七：答辩申请（对应 `0.7`）

### [必做]

- 阅读《提问的智慧》和《别像弱智一样提问》，结合预学习经历撰写不少于 800 字读后感：说明什么是好的提问，以及如何通过 STFW、RTFM、RTFSC 独立解决问题。
- 按入学答辩申请指引完成材料，确认上面的出口清单全部打勾后提交申请。

**[原则] 不用慌，但要持续练习。** 答辩的目的不是筛掉零基础学习者，而是确认你已经准备好面对正式阶段持续出现的陌生问题。遇到困难很正常；停止记录、停止搜索和停止验证才会让困难失去边界。
